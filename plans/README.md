## Findings considered and rejected

- Homebrew install as a Python `halfbold --brew TOKEN` mode (or both CLI and TUI):
  the maintainer chose the Go TUI only on 2026-09-16, because the TUI already
  has the font scan/group/run machinery and the feature is interactive.
- Text-input search against `brew search` per keystroke: rejected in plan 002
  in favour of loading the full `font-*` cask list once (~1.5 s, ~2600 tokens)
  into a Bubbles list with its built-in filter; no new dependency needed.

- Python + Textual picker instead of Go + Bubbles: rejected by the maintainer
  on 2026-09-16; they want Bubbles specifically, shelling out to `uv run halfbold`.
- Note from execution: `bubbles@latest` resolved to v1.0.0 (same
  `github.com/charmbracelet/bubbles` import path, requires bubbletea v1.3.10),
  not v0.x as the plan expected. Accepted; the plan's v1-line intent holds.
- Bubble Tea / Bubbles v2 (`charm.land/...` import paths): not used; plan 001
  pins the v1 line because its API is stable and widely documented. Revisit
  when the v2 line has settled.
- Font kinds as a `halfbold use KIND FAMILY` subcommand: rejected 2026-09-16 in
  plan 003; the CLI is flag-shaped (`--all` is a mode flag), so `--sans`,
  `--serif`, `--mono FAMILY` match it and allow several slots in one call.
- Kind column and "set as active" key in the Go TUI: first deferred, then
  requested by the maintainer later on 2026-09-16; now plan 004.
- Checking that a family's kind matches the slot it is assigned to (`--mono`
  given a sans font): rejected in plan 003; a user may want that, so the CLI
  only verifies the Half font is installed.
- `bFamilyType == 2` gate in `font_kind` (plan 003): dropped during execution
  because the test fixtures' `setupOS2()` leaves `bFamilyType` 0; every real
  text font seen carries 2, so behaviour on real fonts is unchanged. Plan 004's
  Go mirror omits the gate too.
- Browser-page font preview (plans 005/006): rejected 2026-09-16 by the
  maintainer ("i don't want it to open in a webpage"). Replaced by the
  kitty-graphics terminal preview in 008–010. The earlier worry about tmux
  passthrough is handled by documenting `set -g allow-passthrough on`.
- Rendering the real Half font with `calt` applied in the preview: deferred
  in plan 008. Pillow's wheels ship no libraqm, so OpenType features cannot
  be applied; the preview simulates half-bold from the Regular and Bold faces
  with the same `bold_prefix_length` rule, which is visually identical.
- Go-side rasterising (`golang.org/x/image/font/opentype`) for the preview:
  rejected in plan 008; it cannot instance a variable font at two weights and
  has no shaping, whereas Pillow handles variable fonts directly.
- `brew fetch` for Google Fonts casks (plan 010): rejected; it sparse-clones
  the google/fonts repo. The needed TTFs are fetched from
  raw.githubusercontent.com using the cask's `url_specs.only_path` instead.
- Previewing every Homebrew download format (plan 010): `.pkg`, `.exe`,
  `.ttc` and non-Google git casks report "nothing to preview" instead of
  being handled; `.zip`, `.tar.*`, bare `.ttf`/`.otf` and `.dmg` are covered.
- Weakening the Chrome extension's `!important` font rules so preview pages
  render (plan 005): rejected; the preview page uses `!important` itself.
- Wails (Go + webview) instead of Tauri for plan 012: considered because Go
  is already installed and Rust is not; rejected because the maintainer
  named Tauri and Wails would tie the app to the TUI's Go code that 013
  removes. pywebview (Python) rejected for the same reason plus no native
  bundle.
- Tauri `shell`/`fs` plugins or an asset-protocol scope for loading fonts:
  rejected in plan 012; two plain commands (`api`, `read_font`) cover it
  with no capability config.
- Rendering previews in the app via Pillow PNGs: rejected; the webview
  renders the real `-Half.ttf` with `calt`, which is the whole point.
- A `--json` flag on the `halfbold` CLI instead of a separate
  `halfbold-api` script: rejected in plan 011; the CLI's mode flags would
  each need a JSON twin.
- Styling every Homebrew cask row up front (plan 014): rejected; only the
  508 google/fonts casks expose a single TTF by URL, the other ~2100 are
  zips/dmgs up to hundreds of MB. Per-token `brew info` for names (~0.5 s
  each, 2600 tokens) rejected in favour of the formulae index.
